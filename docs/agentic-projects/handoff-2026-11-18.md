## The single recommendation

**Extract the background-worker plumbing out of `app/controller.py` before the
next data-fetching feature, as the first unit of that feature (not a standalone
refactor).**

### Evidence (Observed)

- `app/controller.py` is 5,496 lines: `MainWindow` (line 2670) plus ~16 helper
  classes — six `QObject` workers (`_FetchWorker`, `_OlderHistoryWorker`,
  `_LiveRefreshWorker`, `_SnapshotWorker`, `_Level1Worker`,
  `_ProviderValidationWorker`), cancellation exceptions, and request/route
  dataclasses (lines ~451–1500).
- The same launch / cancel / stale-result-rejection / thread-finished cleanup
  pattern is hand-written six times:

  | Launch site | Method | Line |
  |---|---|---|
  | Chart load | `_start_chart_load` | 3122 (thread at 3149) |
  | Older history | `_on_older_history_wanted` | 3745 (3765) |
  | Live refresh | `_refresh_live_bars` | 3821 (3851) |
  | Provider validation | `_request_provider_activation` | 4856 (4905) |
  | Watchlist snapshots | `_refresh_watchlist_snapshots` | 5072 (5105) |
  | Level 1 | `_refresh_level1` | 5142 (5180) |

  Each copy has its own state fields (e.g. `_snapshot_thread`,
  `_snapshot_worker`, `_snapshot_cancellation_event` at ~2900–2921, reset at
  ~5237 and ~5270; chart loads use `_chart_load_tasks` keyed by generation).
  Shutdown is in `closeEvent` (5476).

### Why now (Inferred)

Planned features that would add another copy of this pattern or modify an
existing one:

- **Earnings dates in top bar** and **past earnings on the chart**: new
  reference-data fetch.
- **Symbol details window with news**: one or more new fetches.
- **Alpha Vantage data source**: new provider path through validation and
  fetch.
- **Pre-market / after-hours data**: changes the chart-load path and cache
  identity (see `docs/agentic-projects/chart-loading-deferred-backlog.md`, "Extended-hours and
  overnight session semantics").

`docs/agentic-projects/chart-loading-deferred-backlog.md` ("Market-data coordinator redesign")
says to revisit this only if "planned work would otherwise duplicate
scheduling and request-acceptance logic." The earnings + news features meet
that condition. The same note warns against assuming the broad coordinator
previously explored is right. **This recommendation is deliberately narrower
than that coordinator.**

### Proposed scope (needs spec + approval before any edit)

1. **Pure move.** Move the six worker classes and their request/route
   dataclasses and cancellation exceptions out of `controller.py` into their
   own module(s) under `app/`. No behavior change. Split
   `tests/test_controller_fetch.py` (1,741 lines, 42 tests) along the same
   lines.
2. **One small helper.** Factor the repeated launch / cancel /
   reject-stale-result / thread-finished / shutdown-join pattern into a single
   helper, and move the six call sites onto it. New features then write only a
   worker plus a result handler.

Out of scope: a market-data coordinator, changes to request-acceptance rules,
provider changes, any user-visible behavior change.

Verification expectation: full test suite green before and after each step;
step 1 is a no-behavior-change move, proven by unchanged tests; step 2 needs
tests for cancellation, stale-result rejection, and clean shutdown through the
production call sites (per AGENTS.md "Integration completeness").

Process: this is complex, cross-cutting work. Follow AGENTS.md gated autonomy
and `docs/agentic-workflow.md`; produce the spec and implementation graph and
wait for approval.

## Assessment of the Copilot review

Overall: accurate in what it claims and appropriately cautious, but it missed
the largest complexity concentration (`controller.py`, 5,496 lines;
`data/cache.py`, 1,950; `app/data_quality.py`, 1,353). It ranked
`ChartExtensionRuntime` (796 lines) first.

| # | Copilot finding | Verdict | Action |
|---|---|---|---|
| 1 | `ChartExtensionRuntime` too broad | Fair but overstated; methods are cohesive around extension state | Skip. Revisit only if drawing/drag changes keep colliding with history-readiness code |
| 2 | Coupling to finplot/pyqtgraph private internals | Accurate (`viewport.py` `MethodType` patches at 628/712, `fplt._x2local_t` at 299, `_xminmax`, `_x2utc`, `_millisecond_tz_wrap`; `window.py` `_start/_end_visual_update` at 310). Already mitigated: `finplot<1.10` cap with comment in `pyproject.toml`; covered by `test_candle_repaint.py`, `test_older_history.py`, `test_plot_manager.py` | Skip. Optional later: inventory of upstream behavior each patch relies on, written when a finplot upgrade is planned |
| 3 | `ChartExtension` base too broad; `render_from_legacy` is migration code | Partly wrong. `compute()` → `render_from_legacy` (`simplechart/extensions/_base.py:655`) is the **primary** path for SMA, EMA, RSI, pivot points, and the five-day marker. Only the name is misleading | Skip. Single base class is a deliberate API choice |
| 4 | `PlotManager` registries becoming broad | More concrete than Copilot showed: seven parallel dicts (`chart/plot_manager.py:130–136`) each hand-maintained in `remove_extension`, `set_visible`, `clear_all`, `active_series_keys`; markers already diverge (own `active_marker_keys` + orphan scrubber) | Defer. Add a small internal handle abstraction only when a feature needs a new render primitive. Earnings markers likely fit existing `MarkerRender`/`VerticalLineRender` |
| 5 | Plugin "isolation" is rollback, not a sandbox | Fair; no docs say plugins are trusted code | Optional: one sentence in README plugin docs. No engineering (see threat model: only credentials are sensitive) |
| 6 | Dict params with transient `_daily_bars` / `_history_complete` | Facts right, but these keys are documented in `simplechart/api.py` and read by SMA, EMA, pivots, AVWAP, so they are public contract; changing them breaks the API | Skip unless a third host-provided key appears |
| 7 | `tests/test_controller_fetch.py` too large | Agreed | Folded into the extraction above |
